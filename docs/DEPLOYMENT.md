# Vercel deployment preparation

No Vercel deployment has been performed. The user previously authorized pushes to the existing private GitHub repository; deployment still requires separate approval.

1. Review milestone completion and launch gaps. Milestone 1 alone is not a launchable authenticated SaaS.
2. Rotate any credential previously disclosed outside the intended secret store. Use separate development/preview/production databases and provider keys.
3. Run type checks, lint, unit tests, production build, browser flows, and database verification for the intended environment. `GET /api/health` is liveness only; `GET /api/ready` checks TLS database access and required application tables. Configure an external uptime monitor to call readiness after deployment. `npm run db:verify-recovery` rehearses a synthetic logical export/restore only; separately confirm provider backups and test a provider restore into a new instance before critical use.
4. Import the approved Git repository into Vercel as a Next.js project. Use Node.js 22.x, the repository root, and the default Next.js output settings. `vercel.json` selects `iad1` near TiDB's `us-east-1` region.
5. Set server-only `DATABASE_URL`, optional `DATABASE_CA_CERT`, `AUTH_SECRET` (random, at least 32 characters), and the canonical `APP_URL` (production HTTPS origin, no path) in each Vercel environment. Gemini remains off unless `GEMINI_ENABLED=true`, `GEMINI_FREE_TIER_CONFIRMED=true`, a server-only `GEMINI_API_KEY`, and an allow-listed free-tier model are configured. Do not enable those flags until the Google AI Studio project has been checked for free-tier model access and has no billing enabled; HoloStack cannot inspect Google billing status. See `AI_INTEGRATION.md`. Never put secrets in Vercel build arguments, browser variables, or source files. Build must succeed without AI or database credentials.
6. The foundation, AI workflow, and intelligence-run migrations are applied to the local development TiDB instance. For any new target, re-verify exact DDL in an isolated schema, review it, then apply from a controlled operator workflow. Do not migrate during `next build` or startup.
7. Deploy only after approval. Verify the production URL, both health routes, auth protection, tenant boundaries, saved project/scenario round-trips, model quotas, and failure handling. A passing `/api/health` alone does not prove database readiness.

Before paid use: confirm provider GA/SLA suitability or move to production PostgreSQL; test provider-managed backup/restore in a separate instance; define recovery time and recovery point objectives; configure persistent error/uptime monitoring and alert ownership; and verify fleet-wide connection limits. Match query/AI timeouts to Vercel function budgets. No user-uploaded binaries in SQL.
